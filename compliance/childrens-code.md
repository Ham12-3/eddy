# ICO Age Appropriate Design Code: checklist

Status: **skeleton** (created in M0). Every standard applies to every Eddy account, whatever the age (ADR-0002).

"Planned approach" summarises SPEC.md. Evidence is added only when the feature and its tests exist.

| # | Standard | Planned approach | Evidence | Status |
|---|---|---|---|---|
| 1 | Best interests of the child | Pedagogy and wellbeing first; no engagement maximising | | Not started |
| 2 | Data protection impact assessment | [DPIA.md](DPIA.md) | | Not started |
| 3 | Age-appropriate application | Neutral 13+ age check; Children's Code defaults for all ages | | Not started |
| 4 | Transparency | Child-friendly notice (reading age about 12) plus full notice, versioned acknowledgement | | Not started |
| 5 | Detrimental use of data | No use of data against the student's interests; no third-party analytics | | Not started |
| 6 | Policies and community standards | Published tutor behaviour rules; no user-to-user content | | Not started |
| 7 | Default settings | High privacy by default; parent visibility off until the student agrees | | Not started |
| 8 | Data minimisation | Birth month and year only; no school, address or phone; pseudonymous ids in prompts | | Not started |
| 9 | Data sharing | No sharing beyond processors listed in the DPIA | | Not started |
| 10 | Geolocation | Never collected; `geolocation=()` permissions policy | | Not started |
| 11 | Parental controls | Student-accepted links with a permanent indicator and a "what my parent sees" preview | | Not started |
| 12 | Profiling | Only for adaptive learning, justified in the DPIA | | Not started |
| 13 | Nudge techniques | No streaks, guilt copy, loss aversion or confetti | | Not started |
| 14 | Connected toys and devices | Not applicable (web app only) | | Not started |
| 15 | Online tools | Download data, delete account and report a concern within two clicks | | Not started |
